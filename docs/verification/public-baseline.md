# Verify an independent public baseline

This check applies to the exact local publication candidate. It does not publish, install, or approve a later changed candidate. Keep raw reports, private comparisons, host configuration and backups outside the source tree.

1. Construct the candidate in a new directory with `git init`, using only explicitly selected reviewed files. Preserve executable modes and empty lifecycle groups. Do not clone, mirror, link worktrees, copy `.git`, or fetch either private repository. Exclude private markers, histories, assessment narratives, scratch data and evidence. Compare each selected file's bytes and mode with the reviewed manifest; record intentional new changes separately.
2. Resolve the current GitHub login, numeric account ID and real name using the authenticated account API. Use the account's applicable GitHub noreply identity for both author and committer, in repository-local Git configuration. Inspect the actual commit headers and message. Do not change old identities or global Git configuration.
3. Review the staged root against Git's empty tree before committing. Record selected paths, modes, blob hashes, SHA-256 file hashes and binary diff checksum. Run `python3 scripts/skills.py check`, `python3 scripts/source_inventory.py check`, the full unit suite, and `claude plugin validate --strict .` and `claude plugin test` from `plugins/elias-mods`. Keep complete outputs and actual exits. Mark unavailable optional type generation or executables as skips.
4. Run the [artifact cases](artifact-preservation.md) and the analytical owners' linked preservation cases. Inspect actual outputs. Prior receipts can support only claims whose complete exercised inputs still match; a skill name or successful build does not prove preservation. Check rights treatment against the maintained source inventory and pinned source evidence, including complete standalone licence companions.
5. Inspect the selected source and every stored Git blob for private data and credentials, including upstream snapshots, patches, fixtures and commit metadata. Review intentional public identities separately from unnecessary contact/account exposure. A scanner is supporting evidence, not sole clearance. Rotate any real leaked credential before remediation is complete.
6. After creating the reviewed root commit, compare `git cat-file --batch-all-objects --batch-check` with `git rev-list --objects --all`, run `git fsck --full --strict`, and inspect every ref and object type. Require exactly the intended root commit, tree hierarchy and selected blobs; no unreachable objects, private commits/tags, remotes, alternates, shallow boundaries, replacement refs or backup refs. Public upstream file contents can naturally share blob IDs with private stores; shared content does not justify inherited history.
7. Create a clean archive of that exact commit into an empty directory. Compare bytes, modes and paths against the manifest, rerun validation and tests there, and perform the [complete bundle export checks](download-preservation.md) using the candidate SHA. Confirm root and bundle legal context, recursive dependencies and conditional-owner guidance survive. Never use the private preparation SHA as the public revision.
8. Review all three host previews against the live personal installation. Record exact additions, changes, removals, globals, links, source and local plugin marketplace/cache effects, backup and rollback. The plugin is a separate installation. Preserve unrelated host settings and stable ownership/plugin IDs. A disposable rehearsal is separate from applying to the personal installation.
9. Review Standards and Spec against a fixed staged snapshot and the observed claim-to-proof matrix. Fix confirmed findings and recheck changed claims before committing. Record the final commit and complete object/ref inventory privately. Any subsequent substantive change needs affected proof and review again.

Local completion leaves external gates open: deliberate personal-source/runtime cutover, authorised creation/push/settings/private archive actions, signed-out browsing and downloads, then actual work-network and work-agent acceptance. Unavailable mandatory rights or preservation proof blocks publication. No local test substitutes for those later surfaces.

For GitHub's noreply formats see [email address reference](https://docs.github.com/en/account-and-profile/reference/email-addresses-reference). Account identity must be checked live; a saved username is insufficient.
