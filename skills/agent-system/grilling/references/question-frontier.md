# Question-frontier method

Use this only when the request has several dependent decisions.

1. Write the desired outcome, hard constraints, current evidence, and decisions already made.
2. Model unresolved decisions as a dependency tree. A question is on the **frontier** only when its answer is needed now and no unanswered parent blocks it.
3. Investigate anything answerable from files, tools, or current sources. Do not turn research work into a user question.
4. Ask every consequential frontier question in one numbered round. For each, explain the consequence and give a recommendation. When a yes/no question fits, phrase it so yes accepts the recommendation; do not force other questions into that form. Use collaborative exploration to make unfamiliar reasoning accessible and develop the user's response within the round. Keep unrelated questions independent.
5. Incorporate the answers, remove closed branches, expose the next frontier, and repeat.
6. Before completion, test for gaps across outcome, users, scope, states, edge cases, data, design, operations, authority, and definition of done as relevant. The definition of done names the independent proof from the [depth pass](depth-pass.md), not the agent's own judgement that the work is finished.
7. Check collaborative exploration's decision-ready standard, then present one coherent agreement. Separate settled decisions, assumptions, exclusions, and any deliberately deferred questions. Briefly surface reusable thinking grounded in this session and ask for explicit confirmation of the agreement.

For a personal or life decision, replace implementation lenses with values, people affected, reversibility, time horizon, cost, downside, and what evidence would change the choice. Do not manufacture certainty where the decision is inherently preference-based.
