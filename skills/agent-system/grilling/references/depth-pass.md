# Depth pass

Independently written for this repository, informed by Felix Rieseberg's "How to be more ambitious" (2026-10-13). Run it once, before the first round, on the plan, decision, or idea as the user stated it. Its job is to make the design tree deeper rather than bigger: it surfaces the questions an expert would ask that the user did not.

## The five questions

Answer each from evidence where you can; investigate before guessing.

1. **One level up.** What outcome sits above the request? If the request is "fix this crash", the outcome above it may be "the app stays crash-free". Name it, and name the standing setup that would let an agent own that outcome without Elias in the loop.
2. **What an expert would add.** What would the best practitioner in this field do here that nobody has asked for? Name the concrete activity, method or tool, and useful output: profile a bottleneck to produce a trace locating the dominant cost, or challenge an explanation against raw data to produce supporting or refuting evidence. Select a supporting skill only when its method contributes to the outcome.
3. **Rawest evidence.** What is the most primary material available: raw data, logs, source, the real user, the running system? Prefer it to summaries and to the user's recollection.
4. **Expert-level target.** Where would an expert set the bar? Ground any stretch target in the baseline, available evidence, and platform and resource constraints; label an unverified target as a hypothesis. If the stated target is far below what is plausibly achievable (5 seconds where 200 ms is achievable), propose the expert target as a stretch with the stated one as the floor.
5. **Independent proof.** What evidence, produced by something other than the agent's own judgement, would show the result is right: a runnable check, the real surface, held-out data, an outside reviewer?

## Feed the tree, do not expand the scope

The pass produces inputs, not decisions:

- An answer that is a **fact** becomes an investigation (dispatch it, as `grilling` describes).
- An answer that **changes scope, ambition, or cost** (raising the altitude, adopting the expert target, adding an expert method) becomes a frontier question with your recommendation. Elias decides; never adopt it silently.
- The answer to question 5 becomes part of the definition of done in the closing agreement.

Skip a question that plainly does not apply and say why in one line. For a personal or life decision, keep questions 1, 3, and 5 and drop the expert-method and target questions unless Elias is optimising a measurable outcome.

## Range without role-play

When another discipline can improve the outcome, name its concrete activity and useful output before selecting a supporting skill or delegating work: an editor cuts a pitch into a decision-ready draft; a forensic accountant reconciles a forecast and reports discrepancies; an accessibility specialist checks keyboard completion and records failures. Use the resulting evidence or artifact in the decision or deliverable. Do not add specialists without a distinct contribution or adopt a persona; a voice adds noise without adding method. This does not require a new agent for each discipline or expand the agreed scope.
