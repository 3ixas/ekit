# Inherited PRs, branches and agent work

Read when resuming or taking over someone else's PR, branch or chat. Resolve the actual head/base and uncommitted state; read original intent, reviews and later user corrections. A contributor's summary and passing mocks are context, not independent proof.

Preserve human author identities, existing human co-author credit, original commits where appropriate, and a link to the original PR. Never guess an email or add generated-tool co-author trailers. When an authorized replacement is needed, keep original contribution and follow-up fixes distinguishable and preserve verified human credit through a squash merge too.

Honor an explicit in-place, stacked or replacement continuation. Do not assume that takeover permits changing another person's PR, closing it, rewriting their branch or publishing a replacement. Explain when the implementation should be treated as reference instead of a safe starting point; a material rewrite needs its scope accepted. Re-read the source PR before publishing a replacement because it may have progressed.

Reassess the idea against current base changes using the relevant intent and comparison steps in the owned `modernize` skill, without treating that reference as an invocation or branch-update authority. Independently reproduce the original problem and prove the continued solution with `verify`. Resume approved implementation only; a delivery endpoint needs the user's Full Stop/Full Send request or separate publishing instructions.

Report what was inherited, what changed, where credit is preserved, observed proof, and any remaining decision.
