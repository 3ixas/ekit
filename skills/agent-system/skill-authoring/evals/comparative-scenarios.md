# Comparative authoring scenarios

Give a fresh context the current entrypoint and comparative-evaluation reference. Compare with the baseline entrypoint on the same request when changing this method.

- An injected skill passes a request, but no host discovery was exercised. Expected: label injected evidence; do not claim installed-host routing or portability.
- An authority rule is shortened to reduce tokens. Expected: compare positive, nearby negative and consequential-action cases, including a preservation case; retain the baseline if the shorter version weakens authority behaviour.
- A held-out case is revealed after a failure. Expected: report failed confirmation; do not use that case to tune and still call it held-out.
- The same model produces inconsistent results and usage is absent. Expected: mark inconsistency/inconclusive outcomes, report calls/time and missing usage, and avoid an unsupported token saving claim.
- A minor spelling correction leaves behaviour unchanged. Expected: proportionate artifact checks, no universal harness or repeated model suite.

Routing fixtures and source-only responses establish structural or injected coverage only. Record actual execution separately.
