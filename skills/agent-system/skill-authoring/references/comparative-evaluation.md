# Comparative skill evaluation

Use for substantial changes to routing, authority or the workflow's observable result. Start from existing scenarios and the failure that motivated the change; do not build a universal harness for a small instruction edit.

Before editing, keep the baseline skill version and select the same realistic requests for baseline and candidate: a positive trigger, nearby requests owned elsewhere, an authority/failure boundary and the main output/action path. State observable criteria before seeing responses. Use fresh independent sessions with the same task, fixtures, model/configuration and tool access; isolate each mutating run. Pass the evidence, not a preferred conclusion.

Record whether instructions were deliberately supplied or discovered through the host's real routing. Injection evaluates the supplied method; host discovery also evaluates selection and loading. A passing injected run or structural routing fixture does not prove installed-host behaviour. Keep candidate bundles outside installed projections; load them explicitly for evaluation.

Inspect actual actions and outputs, not whether an agent can recite the skill. Retain raw response/check evidence, the exact skill version, configuration and Pass, Fail, Skip or Inconclusive per criterion. Separate unavailable access, harness faults and inconsistent outcomes from skill failures. For repeated or model-graded evaluations, load `verify` and its evaluation-validity reference before trusting a score.

Keep additional confirmation requests out of the change proposer's diagnostic context when generalisation matters. Include a case that protects behaviour the change might remove, rather than only the original failure. If the same host/model is all that was exercised, say so; do not infer portability or live discovery from source inspection.

Run the smallest comparison that can change the decision. Record available input/output/cache usage across baseline, candidate, judges, failed calls and retries; otherwise state usage unavailable and report calls and elapsed time. Avoid panels and repeated full suites without an unresolved question. A useful outcome can be no change: retain the baseline when benefit is unproved or the extra instruction cost is not justified. Promotion and activation remain separate decisions.
