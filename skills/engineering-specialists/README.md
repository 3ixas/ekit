# Engineering Specialists

Supply language, platform, data, security, performance, and operational judgment to the owning workflow.

| Skill | Invocation | Purpose |
|---|---|---|
| `api-design` | automatic, supporting | Design HTTP, RPC, event, webhook, or public module contracts around consumers, compatibility, errors, idempotency, and boundary evidence. |
| `ci` | automatic, supporting | Build, debug, or review continuous-integration workflows for fast deterministic feedback, least privilege, safe artifacts, and local parity. |
| `ios` | supporting | Build, run, debug, profile, and verify iOS or SwiftUI applications with Xcode and simulator evidence. |
| `nextjs` | supporting | Build and maintain Next.js applications using current App Router, server/client, caching, routing, and upgrade guidance appropriate to the installed version. |
| `observability` | automatic, supporting | Design or improve production logs, metrics, traces, service objectives, alerts, and runbooks when operating evidence matters. |
| `openai` | supporting | Build or troubleshoot OpenAI API and agent features using current official documentation, safe credential checks, explicit tool boundaries, and meaningful evaluation. |
| `payments` | supporting | Design, implement, review, or verify payment and subscription flows using current provider documentation and strict money, webhook, and idempotency rules. |
| `performance` | automatic, supporting | Measure, profile, trace, and improve software performance through causal experiments and paired evidence. |
| `postgres` | supporting | Design and improve PostgreSQL schemas, queries, indexes, transactions, connections, row security, and migrations using workload evidence. |
| `python` | supporting | Guide Python setup, implementation, typing, quality, CLIs, packaging, documentation, and backend work using the project's actual conventions and current tooling. |
| `react` | supporting | Build or review React components, composition, state, effects, accessibility, and performance using the project's version and architecture. |
| `react-native` | supporting | Build and review React Native or Expo applications with platform-aware components, lists, navigation, animation, performance, and accessibility. |
| `security` | automatic, supporting | Threat-model, harden, or review software involving trust boundaries, credentials, permissions, input, sensitive data, dependencies, or public attack surface. |
| `shadcn` | supporting | Install, inspect, and adapt shadcn/ui components when a project uses shadcn or a chosen reference requires one of its primitives. |
| `supabase` | supporting | Operate Supabase projects across migrations, Auth, row-level security, Storage, Edge Functions, logs, and local or remote tooling. |
| `swift` | supporting | Apply Swift language, concurrency, testing, API, ownership, and performance guidance using the project's deployment target and toolchain. |
| `typescript` | supporting | Apply TypeScript language and type-system discipline to substantive TS or TSX work while respecting the project's compiler and framework choices. |
| `vercel` | supporting | Operate Vercel-linked projects across configuration, deployments, functions, caching, environment variables, logs, storage, and platform diagnostics. |

## Use

`security` owns everyday security judgment and focused reviews. The explicit `security-audit` software workflow owns deliberate repository audits, coverage records, and independent finding verification.

These skills are normally selected from repository evidence by `implement`, `debug`, `code-review`, `verify`, or `release`. Direct invocation remains available for focused work.
