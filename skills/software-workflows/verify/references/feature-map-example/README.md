# Feature-map example

Adapted from Lauren Tan's pstack, MIT; see the bundle's LICENSE.txt and metadata.json. This is an illustrative CLI recipe, not a working harness to copy unchanged. Replace it with commands and behaviour observed in the target repository.

A real guide's index records launch/doctor commands, disposable data ownership, evidence location outside disposable storage, and links to the relevant feature recipes. Read the index before driving a feature. Preserve existing project organization when it already serves this purpose.

- [Create an item](create-item.md): creation, persistence, validation, and cleanup.

Use these four sections in feature recipes; a separate file is optional for a small guide. Cover each material user entrypoint in the requested scope, rather than treating a convenient API path as proof of its UI.
