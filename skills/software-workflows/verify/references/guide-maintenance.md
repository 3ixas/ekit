# Maintain project verification guidance

Use for journeys changed by implementation or an explicit guide audit. Find the existing guide and establish the requested feature scope first. If several guides plausibly match, use project instructions and the work's surface to select; ask only if ambiguity materially changes scope. If none exists, use Set up rather than inventing a maintenance target.

1. Read the index, feature recipes, linked helpers, current implementation, and relevant changes. Check for missing or stale entrypoints, prerequisites, selectors, fixture setup, and cleanup. Cover affected journeys during ordinary implementation; an explicit whole-guide audit covers every indexed feature and checks source for missing user surfaces.
2. Exercise every journey in that scope through the guide's real launch/drive path. Source inspection alone cannot establish a clean audit. Check health before first drive and after surprises; isolate sessions or drive shared owned instances serially. Preserve evidence and clean failed-attempt residue throughout the run.
3. Classify each discrepancy. **Documentation drift:** instructions no longer describe intended behaviour; correct them against source and live evidence. **Harness gap:** intended behaviour works but the driver cannot reach or prove it; correct the harness within scope. **Product regression:** behaviour contradicts the accepted contract; report it without changing expectations to conceal it. A standalone maintenance request does not authorize product fixes. In an implementation task, follow the caller's existing fix boundary.
4. Re-execute every corrected instruction and affected journey on the final working tree. Check evidence survives cleanup and stop only owned resources. Report unavailable prerequisites with attempted paths; inaccessible journeys remain Skip, not verified through another entrypoint.

Report **clean**, **changed**, or **blocked**, with the scope, observed coverage, corrections, evidence, and remaining product/harness/environment gaps. Partial coverage cannot produce a clean whole-guide audit. Keep unrelated product edits out of maintenance changes. Do not automatically schedule audits, delegate workers, open a PR, or publish results; use the calling task's authority and delivery flow.
