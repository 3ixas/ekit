# Budget and evidence

Preparation is part of the same run. Bound fact-finding, Grilling support, reproducer/check construction and implementation work; preserve that spend when the experiment loop starts. Reuse existing decisions and proof rather than rebuilding them. Candidate attempts are bounded hypotheses about an approach or fix, not a quota for every coding increment. Each attempt may contain necessary diagnosis and proving increments; their calls, checks and time still count.

Before the first run, record the check/guard commands, per-command timeout, case set and repetitions, maximum candidate attempts and total evaluation executions. Reuse the project's settings where sufficient. Otherwise plan one baseline, one candidate evaluation and one final confirmation, plus required guards; permit up to three candidate attempts only if their executions and confirmation fit the stated allowance. Repetitions, sensitivity probes, retries and no-change controls consume that allowance too. A command with unknown or unbounded fan-out is not a bounded check: inspect or cap it first.

Use existing recent evidence to estimate per-evaluation cost and duration when comparable. Count all model calls, including proposers, judges, failed calls and retries. Record actual input/output/cache usage and provider-reported cost when available. If usage or pricing is unavailable, report that limitation and cap calls/executions and time instead; never describe an estimate or a call cap as an enforced token ceiling. Set a concrete time allowance and command timeouts before starting. Check the remaining allowance before each launch and do not launch work that cannot leave room for required confirmation/review. Stop or obtain an explicit extension when it will not fit; limits are hard, even while improving. New paid actions require task authority.

Keep analysis local to the hypothesis: examine summary results first, then the few diagnostic traces needed to explain a failure or bottleneck. Save raw evidence for inspection without feeding every transcript to another agent. Skip an extra analyzer when the next change is already clear. Optional investigation must answer an unresolved question within the same allowance; do not add a reviewer panel or duplicate the caller's required review.

Freeze evaluation cases, grading and aggregation through the run. For noisy outputs use comparable baseline/candidate samples and a threshold above resolvable variation; add repetitions only within budget. If the useful effect cannot be distinguished, stop inconclusive. Re-check changed environment/harness identity before resuming, and count any new baseline against the remaining budget. Do not silently shrink the case set or increase repetitions to manufacture a result.

Retain the original baseline and each kept patch. Undo failed attempts with a path-scoped patch against their saved pre-attempt state, checking for intervening edits first. If final confirmation rejects the cumulative result, withdraw the improvement claim and restore only owned experiment changes to the original demonstrated state, or leave a clearly marked unverified patch when safe restoration is unavailable. Preserve the evidence either way.
