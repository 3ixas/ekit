# Research And Decisions

Find evidence, understand systems, develop options, make decisions, and analyze data.

| Skill | Invocation | Purpose |
|---|---|---|
| `compare` | automatic | Develop several competing approaches to comparable fidelity and judge them against one shared brief and rubric. |
| `data-analysis` | automatic | Analyze quantitative, product, or business data with explicit grain, quality, assumptions, reproducible methods, validation, and decision relevance. |
| `data-visualization` | automatic | Design, generate, and verify truthful accessible charts, figures, or analytical dashboards for a defined question and audience. |
| `doc-review` | automatic | Review requirements, plans, specifications, or decision documents for correctness, completeness, internal consistency, and executability. |
| `how` | automatic, supporting | Explain how an existing codebase or system works through entry points, data flow, state, boundaries, ownership, and exact evidence. |
| `ideate` | automatic | Generate and cull grounded possibilities, then present the strongest three as an options round to pick, combine, or reject. |
| `product-thinking` | automatic | Pressure-test one product idea with attributed questions from proven product thinkers and end in a build, test-first, reshape, or drop verdict. |
| `to-questionnaire` | automatic | Turn unresolved decisions that require another stakeholder into a concise structured questionnaire with enough context to answer well. |
| `research` | automatic | Find, evaluate, and synthesize external or current evidence for a question, recommendation, or decision using the strongest available sources. |
| `strategy` | automatic | Define product purpose, users, positioning, success measures, investment themes, and boundaries before feature-level planning. |
| `defuddle` | supporting | Extract clean readable content and metadata from webpages when normal fetching is noisy, incomplete, or cluttered. |
| `why` | automatic, supporting | Reconstruct why code or a system exists using bounded history and evidence while preserving epistemic confidence. |

## Common paths

- Current facts: `research`. Recommendation: research plus a clear judgment.
- Code mechanism or rationale: `how` for how something works, `why` for why it is that way.
- Product idea worth building?: `product-thinking`; generating ideas is `ideate`.
- Expensive alternatives: `compare`, using host-supported isolated candidate work when useful. The owned `parallel` bundle remains paused.
