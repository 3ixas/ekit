# Reference-led Design

References supply taste, product precedent, and concrete constraints. They do not replace reasoning about the user journey.

## Establish the reference set

Use the existing product as a reference for a small consistency change. For a substantial new surface or redesign with an open direction, use external references before fixing it. Reuse the recorded references when the direction is already approved; seek more only for a remaining decision. The user and agent build the set together: the user contributes taste and product context; the agent can find high-signal examples when a category or decision is missing. Collect a small set with distinct jobs:

- a product or flow reference for information architecture and interaction;
- one or more visual references for hierarchy, density, typography, colour, and surfaces;
- component or motion references for details that materially shape the experience.

For each reference, state its role, what it contributes, why it fits this product, and what must not be carried over. For a result from a connected reference library, also record the tool and the query that found it. If supplied references conflict, identify the conflict and propose which quality should govern. Do not average incompatible styles into a generic result.

## Extract design DNA

For each useful reference, record the transferable decisions:

- content priority and reading path;
- page geometry, grid, rhythm, and density;
- typography roles and contrast;
- colour roles rather than isolated hex values;
- component anatomy, state changes, and interaction feedback;
- imagery, icon, texture, border, shadow, and radius treatment;
- motion purpose and pacing;
- platform and accessibility assumptions.

Separate what is useful from what belongs to the source brand. Do not copy a whole screen, distinctive brand expression, proprietary asset, or unlicensed component implementation.

## Converge deliberately

When a consequential direction decision remains unresolved, turn the extracted DNA into a small set of coherent alternatives. Vary meaningful axes such as composition, density, typography, colour temperature, or signature interaction; do not ask for random alternatives. Compare each direction against the product job, references, constraints, states, and likely implementation cost, then converge with the user on one direction and record the rejected choices and anti-goals.

Choose a product-specific signature when it helps the product; deliberate restraint can also be the direction. Distinctiveness should come from the subject, content, and references rather than novelty for its own sake or familiar AI defaults.

## Design the product

Define the primary journey and the decision each screen supports. Include empty, loading, error, success, disabled, permission, destructive, and long-content states that the journey can reach. Specify responsive changes from content priority and available space, not by shrinking a desktop composition. Use realistic representative content and assets where they affect hierarchy or tone; placeholder copy and invented proof can conceal design problems.

Build with project-owned tokens and components. When adapting an external component, verify its license and fit, then integrate its behavior and styling into the local system rather than leaving a disconnected demo fragment.

## Compare the rendered result

Inspect the real interface at representative sizes. Compare it with the reference set on hierarchy, geometry, density, typography, colour, interaction, and craft. Diagnose the largest visible gap, revise a coherent layer, and inspect again. Preserve a written reference map or screenshots when another agent needs to continue the direction.
