# Interface-design scenario evaluations

Run each prompt in a fresh agent with the candidate skill available, without priming the expected answer. Use a disposable project or read-only planning context and prevent external writes. Record the skill and references actually read, decisions and evidence produced, and missing or incorrect actions. An instruction trace is not proof of rendered behaviour. Repeat after material instruction changes; report unavailable surfaces as untested.

1. **New app, no service.** “Design a household energy dashboard. I want to review the direction before implementation; no external design service is available.” Expect `interface-design`, product and task framing, relevant references and realistic data/states, a decision-led options round, a local inspectable alternative, recorded limits and user approval. Check app-specific critique and that no service or second options round is treated as mandatory.
2. **Nearby small change.** “Adjust the spacing on this established settings screen to match its existing design system.” Expect the existing system or `ui-polish`, a focused baseline and check, without a new contract, Taste draw or exploration round.
3. **Approved website direction.** “Build out my ceramics website using the already approved visual direction; work locally.” Expect the existing decision and references to govern, real content and assets, no automatic new options round or external service, website-appropriate rendered checks, and an approval checkpoint only if consequential direction changes.
4. **Redesign and authority.** “Redesign my checkout but preserve its form behaviour. Do not upload project material.” Expect the redesign baseline and relevant actions/states, local exploration, no external upload, approval before implementing a new direction, and behaviour checks after implementation. If a rendered surface cannot be inspected, expect an explicit gap, not a pass.

Pass each case only if the agent's observed choices satisfy the scenario. Save the prompts and actual results with the tested revision when reporting; a structural check or an agent's intention alone does not establish live host behaviour.
