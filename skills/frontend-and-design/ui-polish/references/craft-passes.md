# Focused craftsmanship passes

Use when an established interface feels unfinished across several kinds of detail. Preserve its approved direction. Walk one important journey and capture representative states before editing; use only passes relevant to observed problems. This is an independently written review method, not a measured ranking of design quality.

| Pass | Inspect | Useful correction |
|---|---|---|
| Structure | Main task, hierarchy, grouping, alignment and density. | Fix unclear relationships before local decoration. |
| Typography | Reading measure, baseline, wrapping, numbers and fallback-to-final font changes. | Give each style a job; compare real cold-load and loaded states. |
| Interaction | Immediate feedback, truthful completion, dismissal, focus and rapid interruption. | Keep control responsive; confirm the resulting state and recovery. |
| Resilience | Actual container widths, intermediate sizes, long/empty content, zoom and failed requests. | Prefer layout that absorbs variation and preserves meaningful content and input. |
| Performance | Visible shifts, delayed input, flickering loading feedback and stutter. | Ask `performance` to measure the suspected mechanism; appearance alone is not a diagnosis. |
| Consistency | The same component across pages, themes, content and states. | Correct its shared component or token rather than repeat local overrides. |
| Restraint | Competing emphasis, effects, redundant containers and unnecessary steps. | Remove friction while retaining useful meaning and the product's character. |

## Diagnose before choosing values

- **Optical alignment:** compare visible mass and text baselines as well as bounding boxes. A justified icon correction belongs in the shared component. A universal pixel offset is not a design rule.
- **Semantic spacing:** use tighter spacing within a meaningful group and more separation between groups. Use the project's scale; equal gaps can still communicate the wrong relationships.
- **Nested surfaces:** inspect the relationship between padding and inner/outer radii. Subtracting the inset from the outer radius can be a starting hypothesis, not a compulsory formula; verify the actual silhouette.
- **Depth:** use borders, tint or elevation to explain structure. When shadows are appropriate, keep their direction and surface relationships coherent; layering is an option, not a requirement.
- **Font stability:** compare the real fallback and final font under a cold or throttled load. If their metrics move content, inspect existing framework font handling before considering metric overrides. Never copy example percentages into an unrelated font pair.
- **Loading continuity:** acknowledge input immediately, reserve plausible content geometry and inspect fast as well as slow responses. Avoid indicator flashes without concealing completion or forcing an unnecessary wait.

Choose up to three improvements by user impact, repetition and reach through shared components. Correct broken behaviour and foundations before embellishment. Keep remaining findings visible without expanding the authorised scope. Re-render the same states, exercise affected behaviour and a neighbouring component use, and stop when remaining differences are preferences or outside scope. No timer, numerical craft score or full checklist is required.

## Primary references

[Web Interface Guidelines](https://vercel.com/design/guidelines) informs optical corrections, feedback and loading continuity; [Improved font fallbacks](https://developer.chrome.com/blog/font-fallbacks) explains metric-compatible fallbacks; [Designing Beautiful Shadows](https://www.joshwcomeau.com/css/designing-shadows/) informs coherent elevation. These are reference sources, not copied recipes; metadata records the reviewed response fingerprints.
