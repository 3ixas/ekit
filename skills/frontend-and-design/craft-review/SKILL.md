# Craft Review

## Outcome

An evidence-backed explanation of why an interface feels unfinished, with up to three recommended priorities and clear handoffs. This is a diagnostic review of an existing web interface, not an implementation or readiness verdict.

## Method

1. **Bound the review.** Read project instructions and the approved design direction. Establish audience, primary journey, target surfaces and the requested boundary from available context; ask only for missing choices that materially change the review. Reuse the project's preview and tools.
2. **Inspect before judging.** Walk the journey and representative reachable states. Record route, state, viewport, input method and supporting captures or measurements. Use safe test data; do not trigger real sends, purchases, deletions or account changes. When only screenshots are available, assess visible composition and mark interaction, performance and other unobserved behaviour unverified.
3. **Diagnose across dimensions.** Read [review lenses and findings](references/review-method.md). Examine visual precision, interaction quality, technical smoothness, behavioural completeness, system coherence and restraint. Select relevant checks rather than demand an exhaustive matrix. Distinguish an observed defect, an untested causal hypothesis and an aesthetic preference.
4. **Prioritise.** Explain the user consequence and likely cause of each material finding. Prefer broken behaviour, foundations and repeated shared-component faults before embellishment. Recommend up to three improvements; do not invent findings to fill a quota or assign a numerical premium-design score.
5. **Hand off.** Give each finding a proposed correction, responsible existing owner and observable verification method. State review coverage, what held up, unavailable evidence and remaining uncertainty. Return the brief in the conversation unless a durable review artifact is requested; do not create a new project contract by default.

## Boundaries

Inspect and report; do not edit product code, fix findings, install services, upload private project material or start a redesign from this review. A separately authorised implementation task can use the brief through the existing owners. Screenshots do not prove keyboard, touch, assistive-technology or runtime performance. Missing access is a limitation, never a clean result. Follow current authoritative sources for standards; illustrative timings, offsets and CSS values are not universal rules.
