# Voice and Style

`VOICE.md` describes the author across contexts. `STYLE.md` describes a publication, project, team, or deliverable. Neither file is required.

When the user asks for their voice, first read any voice profile named by the active personal instructions or supplied with the request. If no profile is available, inspect representative samples already authorized and relevant to the task. If none exist, preserve the source draft's observable voice. Ask for a sample only when matching the person, rather than simply producing strong prose, materially affects the result. Never invent a personal voice from generic preferences.

## Build from evidence

Use several representative samples written or explicitly approved by the author. Separate stable tendencies from traits caused by one format. Record observable choices and useful examples; avoid labels such as “warm” or “professional” unless they are translated into decisions an editor can apply.

Useful evidence includes how the author opens, develops claims, uses examples, expresses uncertainty, varies rhythm, handles humour, addresses readers, and ends. Record phrases or habits to avoid only when the author has rejected them.

## Apply profiles

Authority order is: the current request, supplied facts and source material, project `STYLE.md`, author `VOICE.md`, then general editorial judgment. A profile guides decisions; it does not override the purpose or force every characteristic into every sentence.

If the source draft conflicts with a profile, preserve the source unless the task asks for alignment. Never infer biography, beliefs, or experiences from stylistic patterns.

## Maintain

Update a profile from repeated evidence or explicit feedback, not one isolated edit. Keep it brief enough to use. Examples should show the principle without becoming reusable copy that makes future writing repetitive.
