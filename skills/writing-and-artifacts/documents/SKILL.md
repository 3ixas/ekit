# Documents

Produce an editable Word document and evidence that its saved structure and pages satisfy the request. Read [document operations and verification](references/workflow.md) for editing, revision, and layout branches.

1. Inspect the original before deciding whether to edit it or create a new file. Record the requested audience, format, page constraints, and protected content. Use `writing` for prose choices; preserve user wording and identifiers unless editing them is requested.
2. Discover a document-capable tool and a renderer in the current host. Use an approved document model or office application, not raw string substitution over an archive. Keep the original and write a distinct output unless replacement is authorised.
3. Follow the document's styles and section structure. Add only the requested content or formatting changes. Handle comments and tracked changes through a tool that supports them; never silently flatten them.
4. Save, reopen, and check the affected content and structure. Render the changed pages, including adjacent pages when flow can move, then inspect headings, table splits, footnotes, margins, and clipping. Correct observed defects and repeat the affected checks.
5. Deliver the file path, inspected pages, and any remaining limitation. A successful save proves neither pagination nor revision fidelity; state unavailable checks precisely.

Local conversion and inspection are not authority to upload a document, send it, share it, or replace the source. A missing renderer permits a clearly labelled structural draft, not a claim that layout is verified.
