# Obsidian vault operation contract

## Resolve authority

Read the live vault-level and nearest folder instructions before editing. Personal Knowledge is authoritative for personal facts, reflections, goals, and durable notes. A project repository remains authoritative for its implementation state and decisions. Link between them rather than copying volatile detail.

## Retrieve proportionately

Start from named notes, indexes, links, properties, or search terms. Expand only when the current question requires it. Do not scan unrelated personal areas. Treat indexed or generated summaries as leads until checked against the canonical note.

## Preserve authorship

Keep exact personal wording, uncertainty, reactions, ratings, and status distinctions unless rewriting is requested. Do not infer an opinion, completion, or score from surrounding context.

## Write safely

Inspect the existing note and its local conventions. Draft consequential structural changes before applying them. Preserve frontmatter types, wiki links, embeds, callouts, and task syntax. Stage only files changed for the request. After writing, re-read the changed section and validate affected links, headings, queries, or Bases views.

Use Markdown, Bases, Canvas, or CLI-specific guidance only when that format is actually involved. Broad automatic ingestion and generic LLM Wiki duplication are outside this owner.
