# Personal commitment reviews

Use this branch for requests such as “review my current commitments”, “check my focus” or a personal goal/life-direction review. Ordinary capture remains the normal Obsidian path; code review, project strategy and teaching retain their own owners.

For the four-level planning context, also read [personal planning](personal-planning.md). The dedicated `planning` skill owns daily and weekly operational review. Preserve this contract's review dates and evidence rules; use an explicit live migration record to distinguish the current task library from a scheduler awaiting cutover.

## Resolve context in a fresh session

Locate the active vault through current instructions/configuration; read its AGENTS and system configuration. Resolve the active planning page(s), review guide and review record root from that configuration. Read the active page and latest relevant confirmed review before asking the user to repeat context. Personal facts, reasons, providers and review rules stay in the vault, not this skill.

Follow the live review guide. Distinguish a commitment's adoption/start date, next review checkpoint, routine follow-through check, deferred trigger and longer-term direction review. Review only the requested scope plus due/overdue or materially affected items. Do not reset unreviewed dates, backdate starts, turn review dates into expiry dates, or revive archived planning systems. A read-only check is not itself evidence of a completed review.

## Evidence and authority

Use the live configured task provider and only relevant evidence; never prefer a stale provider from memory. Scheduling does not prove completion. If the integration or completion history is unavailable, state the limitation and use the user's account; missing data is unknown.

Discuss follow-through and propose a proportionate adjustment. Preserve the user's reasons and confirmed commitments. Record or update only within the request's authority; inferred personal goals require agreement. Follow the live guide for dates, review records and links. Task/Calendar writes need their own authority and verified provider semantics. No automatic catch-up debt, new quotas, equal-area obligations, publication or deletion.

## Proof

Reread the updated page and record; verify links and dates, confirm unreviewed items remain unchanged, and report exactly what was recorded versus proposed. A fresh-context scenario must resolve the current model without old chat context; an unavailable-provider scenario must preserve unknown completion and perform no provider writes.
