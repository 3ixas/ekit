# Personal planning

One conversational workflow with four entry points. The purpose is choosing, starting and advancing meaningful work with sustainable commitments. Do not turn it into a long questionnaire, a replacement task manager or a coaching interview about concentration when the request concerns the system.

## Resolve context once

1. Read the live vault instructions and configuration. Resolve active planning pages, the operating manual, standing practices, weekly-plan root, review guide and timezone from those files. Follow links; never bake personal goals, service IDs or vault paths into this skill. A missing planning note is missing context, not permission to reconstruct old goals from memory.
2. Read only the context needed for the requested level. Start with current focus and the manual; retrieve project detail only when it changes a decision. Use the latest relevant confirmed review for continuity. Ask one focused question only when an unresolved choice materially changes the plan.
3. Resolve the task library, scheduler and fixed-commitment provider separately. During migration, a prepared task library is not proof of scheduler cutover. Follow the explicit transition record for permitted reads/writes; do not silently choose a provider or resume an old scheduler because a generic instruction still names it. If records conflict without an explicit transition, state the conflict and resolve it before provider writes. An unavailable connector does not invalidate a reflection, but prevents claims about unseen tasks or availability.
4. Read the relevant task selection, actual deadlines and fixed commitments through available supported tools. Discover IDs, labels, fields and pagination live. Bound the period and retrieve the minimum required metadata; do not send employer details to a personal service. Calendar blocks are intentions, not proof of execution. Missing completion history stays unknown.

The working hierarchy is **direction → current focus → this week → tomorrow** where adopted by the live manual. It is not a demand for separate yearly, quarterly and monthly goal sets. Current focus persists until deliberately changed; nine life areas do not imply nine active workstreams.

## Review my long-term direction

Read the existing direction and reasons, relevant confirmed decisions and the change the user wants to consider. Use the commitment-review contract for evidence, authorship, dates and recording. Explore the trade-off at the requested scope; do not interrogate every area or break distant aspirations into tasks. Distinguish a suggestion from an adopted personal ambition.

Produce the proposed wording or decision, what it changes for current focus, and any question necessary to settle it. Once agreed, save within the request's scope and preserve unchanged reasons, adoption dates and review checkpoints. Reviewing direction does not activate every related project or schedule work.

## Review my current focus

Read direction, active commitments, deferred triggers and relevant review evidence. Help decide what to advance, maintain, reduce or defer within present capacity. Use concrete recent outcomes or the user's account instead of task counts as a proxy for progress. An interesting idea does not become current focus merely because it was captured.

Produce a short changed/unchanged decision and its consequence for the week. Record agreed changes only; preserve unreviewed items and their dates. A passed deferred checkpoint is an invitation to assess circumstances, not automatic activation. Do not invent practice quotas or new milestones to make the page look complete.

## Operational planning

The dedicated `planning` skill owns daily and weekly Todoist review, task reconciliation, stale-item tracking and time-block proposals. When supporting it, supply the live Obsidian direction, current focus, standing defaults and relevant weekly note. Do not run a competing shortlist-only planning workflow.

## Review, adjust and save

Review-and-adjust fits within these conversations; it is not a fifth mandatory ritual. Use ordinary judgement for overruns and interruptions. Revisit higher levels only when the evidence or the user calls for it. Track pilot evidence only when a pilot is deliberately started; meaningful outcomes, reliable starts, sustainable workload and planning overhead matter more than a full calendar.

A request to plan permits reading context and proposing a plan. A request to save the settled plan permits that scoped note write; a request to apply its task changes permits those specified provider writes. Do not repeatedly seek authority already given, but never infer approval of new commitments, task completion, account cutover, messages, payments or destructive cleanup.

Before mutation, inspect existing objects and the live provider contract. Send only changed fields, preserving complete arrays where updates replace them. Check for duplicates before creates and re-read after uncertain results instead of blindly retrying. Afterward, re-read notes and tasks, validate links and the selected period, and confirm unrelated fields/checkpoints remain intact. Report **proposed**, **saved** and **verified** accurately, including missing evidence. This workflow supplies neither credentials nor automatic scheduling authority.
