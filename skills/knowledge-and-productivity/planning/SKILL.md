# Planning

## Outcome

An intentional, realistic day or week in which every relevant loose end is accounted for and the user's agreed Todoist changes are verified. Read Obsidian for personal direction; use Todoist for this requested planning workflow and Calendar for fixed commitments. A calendar block is a plan, not evidence of work done.

## Method

1. Resolve the requested day or week in the user's configured timezone. Read the live vault configuration, planning manual, current focus and relevant weekly plan. For direction or focus reviews, use the existing `obsidian` commitment-review method; the user can request these through planning too.
2. Follow [the review workflow](references/review-workflow.md): scan every active Todoist project, section, parent and child, including inbox, deferred and exploration; paginate. Reconcile planned work with activity history, existing snapshots, deadlines and calendar. Keep unavailable history or incomplete coverage explicit.
3. Use the `grilling` skill as a supporting method for focused question rounds, following the planning-specific adaptation in [the review workflow](references/review-workflow.md). Order decisions by urgency and priority, while also surfacing eligible older work. Account for every relevant item; keep undecided items visible and resume them if the session stops. No silent completion, automatic rollover or manufactured catch-up debt.
4. Propose realistic blocks around existing commitments. Elias decides each disposition and final time. Apply each agreed change with the Todoist connector, preserving real deadlines and recurrence, then read back and report actual results. Do not create duplicate calendar events or change integration settings.
5. Use [the private state contract](references/private-state.md) to track reviewed task IDs/dates, agreed task IDs/times and unresolved task IDs. A 30-day stale timer resets only after an actual decision. Snapshot the verified agreed plan; a snapshot or elapsed time is not proof of completion.

## Boundaries

Personal facts remain in the vault; employer-confidential details stay out of private planning notes and state. A planning request authorizes reads and discussion. The user's decisions authorize the specific requested task and note changes; do not re-confirm already agreed actions. Deletion, completion, integrations and messages require their own applicable authority. Preserve source-provider data during unresolved migration; surface gaps instead of claiming a complete review.
