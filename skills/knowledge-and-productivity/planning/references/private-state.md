# Private planning state

The live vault configuration supplies `planning_workflow.review_state`, a private local JSON path. The skill's helper `scripts/planning_state.py` operates on that path; do not store personal state inside the public skill repository. Discover the Todoist user ID live and pass `--account ID` on every helper call. An existing record for a different account fails closed: do not reset or merge it; report the mismatch and use a separately authorised account-specific record. An absent file is an empty state; malformed existing data must never be overwritten.

The private record contains the Todoist account ID, task IDs with their last actually reviewed local dates, a pending task-ID queue, and day snapshots containing only task IDs and local times plus a complete/partial flag. It never contains task names, descriptions, reasons, priorities, notes, credentials, calendar details or completion claims. Pending IDs are a recovery checkpoint, not proof of a decision or of a failed write. Retrieve current context through the connector after a restart. If the specific decision or approved change cannot be recovered from the conversation, ask instead of guessing.

- `show --state PATH --account ID` reads the state without creating a file.
- Before a review, `stale --state PATH --account ID --today YYYY-MM-DD` reads a JSON array on stdin. Each item contains `id`, `created_at` (earliest verified date or null), `recurring` and `waiting_for_future_trigger`; it reports eligible, unknown-age and held IDs. The agent resolves provenance, blockers and meaning from live evidence. A scan never resets the review clock.
- Before discussing identified loose ends, `queue --state PATH --account ID` reads a JSON array of IDs from stdin and merges it into pending. On an interruption or failure, keep the ID pending. After a decision and any resulting write are verified, `resolve --state PATH --account ID --task-id ID` removes the ID from pending. If no provider write was requested, resolve after the decision. Do not remove an unanswered or uncertain item.
- After an actual decision, `review --state PATH --account ID --today YYYY-MM-DD --task-id ID` records that ID/date. Never call it for a scan or unanswered question. A verified decision's review date and pending resolution are distinct; on failure keep it pending even if it was reviewed.
- As day-plan task changes are verified, `snapshot --state PATH --account ID --date YYYY-MM-DD` reads a JSON array of `{id, time}` from stdin and writes a partial snapshot. Add `--complete` only once every agreed task/time has been applied and checked. `time` is a local ISO datetime or null for an agreed undated task. For each checkpoint, merge all still-valid, verified entries from the existing snapshot with the new verified entries; remove or replace an entry only when the user intentionally changes or deselects it. A later agreed replan can replace that day's snapshot. Record only successful reads/writes; never label an incomplete snapshot complete.

The helper locks and writes atomically with private file permissions. It validates inputs and fails without overwriting malformed existing state. Snapshots and activity logs are evidence, not proof of execution; disclose missing or incomplete coverage. User decisions control task changes; the record adds no provider-write authority. Use the host's authorised local-vault access mechanism if the path is outside its writable workspace.
